\title{What a Mutation Regime Can Know About a Function}
\author{\IEEEauthorblockN{Anonymous Author(s)}\IEEEauthorblockA{Affiliation}}
\maketitle
\begin{abstract}
Mutation testing measures a test suite by the fraction of a fixed family of \emph{mutant} programs it distinguishes, and a score of one is read as evidence of adequacy. What such a score establishes about the program under test has never been characterized independently of a particular program, suite and mutant pool. We give that characterization for \textbf{output mutation}, which perturbs the returned value; extreme, Descartes-style mutation is its constant case. We ask when a full score against one regime guarantees a full score against another, for every program and every suite. For adequacy an output operator is exactly its \textbf{footprint}, the set of values it changes, and our main theorem (Theorem 3.2) answers the question: a \emph{finite} regime $\Pi$ is \emph{sufficient} for a target class $\Gamma$ iff every target footprint is the union of the $\Pi$-footprints it contains, while an infinite regime obeys a finite-avoidance form of the same law. The characterization is constructive: when it fails, its proof yields a program and a suite on which $\Pi$ scores one and $\Gamma$ does not. Its consequences locate what a passing score can \emph{know} about a function. On $n$ output values the \textbf{minimal sufficient regime} consists of the $n$ singleton \emph{value guards}, and Descartes constants are sufficient iff $n = 2$. A full score \textbf{knows exactly output coverage}: the suite exercised every value the program can return, and nothing more (Theorem 4.5). A finite absolutely sufficient regime exists only on finite return types, and deciding sufficiency is polynomial for value tables, decidable for Presburger-definable footprints and undecidable for computable operators (Theorem 5.2). Under a weak oracle the theory relativizes and characterizes the \emph{pseudo-tested} method (\S 9). We separate three kinds of knowledge: whether a mutant changes the output, whether the suite's assertions see the change, and whether the change matters. Our theory settles the first two within its model; the third, the \emph{intent residual}, needs a specification from outside the program (\S 10). Applying uniform output operators to the test suites of four Python libraries (131 functions, 985 mutants), we find 9\% of the functions with a type-preserving constant pseudo-tested under the value oracle. Our model predicts that a constant mutant is detected exactly when one of its point changes is, which holds whenever a suite checks results call by call. That prediction held for every function where it was testable, except two whose type-changing constant crashes a test before its assertion (\S 9.5). Some sampled functions have side effects, so this tests the output-transformation prediction on real, partly stateful, executions rather than validating the pure-function model as a whole. The central characterization and its corollaries are mechanized in Lean 4 / Mathlib, and a theorem ledger identifies the results proved only on paper. Our artifact includes a decision procedure for finite sufficiency that returns the theorem's counterexample.
\end{abstract}

\section{Introduction}
\setcounter{subsection}{0}
\subsection{The question}
Take a function with three possible return values $\{a, b, c\}$ and a test suite whose tests happen to observe only $a$ and $b$. Under extreme mutation, which replaces the body with \texttt{return a}, \texttt{return b} or \texttt{return c}, every mutant dies, because each constant differs from some observed output, so the suite scores one. Yet the fault ``returns $b$ where it should return $c$'' survives, since no test ever sees $c$ (Example 4.4). A perfect score against one operator family certified nothing about a fault that another family expresses.

This paper answers, for one class of operators, the question that example raises: \emph{when does a full score against one mutation regime guarantee a full score against another, for every program and every suite?} We call this relation \textbf{sufficiency} (Definition 3.1). It is the precise form of a plainer question, namely \emph{what does a passing score let you know about the function?}

For \textbf{output mutation}, operators that perturb a function's returned value regardless of how it was computed, the answer is exact. An operator matters to adequacy only through its \textbf{footprint}, the set of values it changes (Proposition 2.4). A finite regime $\Pi$ is sufficient for a target class $\Gamma$ iff every target footprint is the union of the $\Pi$-footprints it contains (Theorem 3.2), and an infinite regime obeys a finite-avoidance form of the same law (Theorem 3.2b). On three values the constants fail because no constant's footprint fits inside $\{c\}$. Our characterization is constructive: when it fails, its proof builds a program and a suite on which $\Pi$ scores one and the target does not, and our artifact implements it as a decision procedure that returns this counterexample.

\textbf{Why this is not a known result.} Adequacy of a test set relative to a class of alternative programs is due to Budd and Angluin~\cite{budd1982} and Howden~\cite{howden1982}; both fix the program and its class, and neither relates adequacy for one class to adequacy for another. Three later results come closest to doing so, and \S 11 compares all of them precisely. Alshahwan and Harman~\cite{alshahwan2014} select tests whose outputs differ, their \emph{output-uniqueness} criterion; it is a test selection criterion evaluated empirically. Our Theorem 4.5 shows that a full score against \emph{all} output operators coincides with observing every reachable output, the absolute special case, whereas Theorem 3.2 is a statement about the relation between \emph{any two} regimes, which output uniqueness leaves untouched. \emph{Minimal} and \emph{dominator} mutant sets (Ammann et al.~\cite{ammann2014}) are defined relative to a fixed test set and mutant pool, and true semantic subsumption, the order they approximate, is undecidable (Kurtz et al.~\cite{kurtz2015}). \emph{Sufficient} replacement sets for relational and conditional operators (Kaminski, Ammann and Offutt~\cite{kaminski2013}; Just et al.~\cite{just2012}) are program-independent, but each is derived for one operator schema from the truth table at the point of mutation. Theorem 3.2 is a necessary-and-sufficient characterization over the whole output-operator class, quantified over all programs and suites.

Program-independence comes from the object. A program-text mutation \emph{schema} produces a mutant that depends on the \emph{text} of the program rather than on the function it computes alone, so in general its detection varies across programs computing the same function, and uniform statements about it have to be earned schema by schema; the point-of-mutation results above earn them for relational and conditional operators from the operator's own truth table. Output operators act on the returned value alone, so their detection factors through the footprint for the whole class at once (Proposition 7.2). That general footprint reduction, rather than an impossibility result for other schemas, is what makes an exact theory available here.

\setcounter{subsection}{1}
\subsection{The frame: three kinds of knowledge}
A passing score bears on three different questions about a function, and our theory answers them to different extents.

\begin{itemize}
\item \textbf{Semantic distinguishability: does a mutant change the output?} This is $\Mov(p)$, and \S \S 2--8 answer it completely under an exact oracle. A full score against all output operators is equivalent to output coverage (Theorem 4.5). Executions supply positive witnesses, while unresolved equivalent mutants prevent unconditional automation in general, even for Boolean outputs (\S 10).
\item \textbf{Observational distinguishability: do the suite's assertions see the change?} This is the oracle-relative detection set $\Det_\omega(p)$ (\S 9). The difference $\Mov(p) \setminus \Det_\omega(p)$ is exactly what a given oracle hides, and it is what makes a covered method pseudo-tested.
\item \textbf{Specification relevance: does the change matter?} Which of the distinctions the regime certifies bear on what the program is supposed to do is fixed neither by the program text nor by the oracle. We call it the \textbf{intent residual}. It requires a specification from outside the program: an authored intent test, a reference implementation or a formal contract (\S 10).
\end{itemize}

Within its model this paper characterizes the first two layers, and it locates the boundary to the third.

\setcounter{subsection}{2}
\subsection{Contributions}
\begin{enumerate}
\item \textbf{The sufficiency characterization} (\S 3; Theorems 3.2 and 3.2b, machine-checked): a finite regime $\Pi$ is sufficient for $\Gamma$, uniformly over all programs and suites, iff every target footprint is the union of the $\Pi$-footprints it contains; arbitrary regimes satisfy the finite-avoidance form. It rests on the \textbf{footprint reduction} (\S 2): for adequacy an output operator \emph{is} its footprint. Its proof is constructive, and our artifact turns it into a decision procedure with re-checkable counterexamples.
\end{enumerate}

Every remaining result is a consequence or an extension of that characterization.

\begin{enumerate}
\setcounter{enumi}{1}
\item \textbf{The minimal sufficient regime and the ceiling} (\S 4): the $n$ value guards are the minimal absolutely sufficient regime; constants are sufficient iff $n = 2$; a full score knows exactly output coverage.
\item \textbf{Existence and effective boundaries} (\S 5): finite absolute regimes require finite return types; deciding sufficiency is polynomial, decidable or undecidable according to the footprint representation. This is distinct from deciding program reachability or equivalent mutants.
\item \textbf{What structure alone leaves open} (\S \S 6--7): coupling is not entailed for output mutation; detection factors through the footprint, which is why the theory is program-independent.
\item \textbf{The cost of the knowledge} (\S 8): the minimum certifying suite has $|f(D)|$ tests, the teaching dimension.
\item \textbf{The oracle-relative boundary} (\S 9): the development relativizes to a weak oracle and characterizes the pseudo-tested method under the mixed reading production tools use; \S 10 separates this observational layer from the intent residual.
\item \textbf{An experiment with the model's operators} (\S 9.5): uniform output operators applied to the test suites of four Python libraries, measuring pseudo-testedness and checking the output-transformation prediction on real execution traces, some of them from stateful code.
\end{enumerate}

Our central characterization and the corollaries listed in the theorem ledger (\S 11) are mechanized in Lean 4 / Mathlib, stated over programs \texttt{f : D \ensuremath{\to} R} and finite suites, and the ledger identifies the results proved only in this paper (\S 11).

\section{The model}
\begin{definition}[2.1 (program, suite, output operator)]
A program computes a total function --- its \emph{denotation} --- $f : D \to R$, from inputs $D$ to a return type $R$ with $|R| \ge 2$. A \emph{suite} is a finite $T \subseteq D$. An \emph{output operator} is a total map $p : R \to R$; it produces the mutant $p \circ f$ (run the program, then perturb the result). A \emph{regime} $\Pi$ is a set of output operators.
\end{definition}

\begin{definition}[2.2 (footprint)]
The \emph{footprint} of $p$ is $\Mov(p) = \{ r \in R : p(r) \neq r \}$, the values it changes. Write $I = f(D)$ for the program's \textbf{reachable} outputs and $O = f(T) \subseteq I$ for the suite's \textbf{observed} outputs.
\end{definition}

\begin{definition}[2.3 (equivalence, killing, score)]
$p \circ f$ is \emph{equivalent} iff $p(f(x)) = f(x)$ for all $x \in D$; $T$ \emph{kills} it iff $p(f(x)) \neq f(x)$ for some $x \in T$; the score $\score_\Pi(f,T) = 1$ iff $T$ kills every non-equivalent $p \circ f$, $p \in \Pi$.
\end{definition}

\begin{proposition}[2.4 (an operator is its footprint)]
For any $f$, $T$, $p$: \[\begin{aligned} p \circ f \text{ equivalent} &\iff \Mov(p) \cap I = \varnothing,\\ T \text{ kills } p\circ f &\iff \Mov(p) \cap O \neq \varnothing. \end{aligned}\] So whether $p$ is a non-equivalent survivor depends only on $\Mov(p)$. Equal footprints are interchangeable, and $\score_\Pi(f,T)$ depends only on $\{\Mov(p) : p \in \Pi\}$.
\end{proposition}

\begin{proof}
$p\circ f$ is equivalent iff $p$ fixes every element of $I = f(D)$, i.e. $\Mov(p)\cap I = \varnothing$. $T$ kills $p\circ f$ iff some $x\in T$ has $f(x) \in \Mov(p)$, i.e. $\Mov(p)\cap f(T) = \Mov(p)\cap O \neq \varnothing$. Both read only $\Mov(p)$ against the fixed sets $I, O$.
\end{proof}

\begin{remark}[2.5 (every subset is a footprint)]
For $|R| \ge 2$ every $S \subseteq R$ is some operator's footprint: fix $a \neq b$, let $q(a) = b$ and $q(x) = a$ otherwise (fixed-point-free), and set $p(x) = q(x)$ for $x \in S$, $p(x) = x$ otherwise. So footprints range over the entire powerset, and a regime's adequacy content is exactly the family $\Foot(\Pi) = \{\Mov(p) : p \in \Pi\}$. \emph{Where} an operator sends the values it moves is invisible to adequacy, and everything below rests on that fact.
\end{remark}

\textbf{The knowability question, stated.} Proposition 2.4 defines non-equivalence by intersection with $I$, and observed killing by intersection with $O$. Running a finite suite observes the latter, and for a surviving mutant it leaves the former undecided. \emph{What a passing score lets you know about $f$} is therefore a question about set systems, which \S 3 takes up.

\begin{remark}[2.6 (scope, and where the observational layer enters)]
\S 2--\S 8 assume an \textbf{exact output oracle}: a mutant is killed exactly when a test yields a different return value (Definition 2.3), so the suite observes the full output. This is the load-bearing assumption, and it is where the second kind of knowledge of \S 1.2 enters. Under a weaker oracle a \emph{covered} mutant can survive because no assertion inspects the changed value, which is the pseudo-tested method, and \S 9 relativizes the whole theory to make this precise. Two simplifying assumptions remain: denotations are pure total maps (void methods, exceptions and effects are out of scope), and an operator perturbs every returned value identically (a statement-level mutation of one \texttt{return} site is not of this form).
\end{remark}

\setcounter{section}{2}
\section{The sufficient regime}
\begin{definition}[3.1 (sufficiency)]
A regime $\Pi$ is \textbf{sufficient for a target class $\Gamma$} iff for \emph{every} program $f : D \to R$ and \emph{every} finite suite $T$, \[ \score_\Pi(f,T) = 1 \ \Longrightarrow\ \score_\Gamma(f,T) = 1. \] $\Pi$ is \textbf{absolutely sufficient} iff it is sufficient for $\Gamma = \mathcal{T}(R)$, all output operators. The quantifier over all $(f,T)$ removes both the program-text and the suite relativity of prior completeness notions: sufficiency asks what a kill certifies \emph{as such}, not on some corpus. Here $D$ \textbf{varies}, since the quantifier ranges over all input domains and all $f : D \to R$. By Proposition 2.4 what matters is only the pair $(I, O) = (f(D), f(T))$ with $O \subseteq I$, and \S 11's \texttt{realizable} shows every such pair is met by an actual program, so quantifying over programs and over $(I,O)$ pairs coincide. The separating program built in Theorem 3.2's proof uses a finite domain of size $|D| = |A| + 1 \le |\Pi| + 1$, one escape point per operator that moves $b$, plus $b$ itself.
\end{definition}

\begin{theorem}[3.2 (footprint characterization)]
Let $\Pi$ be finite. Then $\Pi$ is sufficient for $\Gamma$ iff \[ \forall g \in \Gamma,\ \forall b \in \Mov(g),\ \exists p \in \Pi:\quad b \in \Mov(p) \subseteq \Mov(g), \] equivalently: \textbf{every target footprint is the union of the $\Pi$-footprints it contains}.
\end{theorem}

\begin{proof}
($\Leftarrow$) Assume the condition; fix $(f,T)$ with $\score_\Pi(f,T)=1$ and non-equivalent $g\in\Gamma$. By Proposition 2.4 pick $b \in \Mov(g)\cap I$; take $p\in\Pi$ with $b\in\Mov(p)\subseteq\Mov(g)$. Then $b\in\Mov(p)\cap I$, so $p\circ f$ is non-equivalent, hence killed: $\Mov(p)\cap O\neq\varnothing$. Since $\Mov(p)\subseteq\Mov(g)$, also $\Mov(g)\cap O\neq\varnothing$, so $T$ kills $g\circ f$.

($\Rightarrow$) By contraposition. Suppose the condition fails at $g\in\Gamma$, $b\in\Mov(g)$: every $p\in\Pi$ with $b\in\Mov(p)$ has an escape point $a_p\in\Mov(p)\setminus\Mov(g)$. Let $A = \{a_p\}$; finite (as $\Pi$ is), with $b\notin A$. Take $I^\star = \{b\}\cup A$, $D = I^\star$, $f = \mathrm{id}$ (so $I = I^\star$), and $T = A$ (so $O = A$). Every non-equivalent $\Pi$-mutant dies. If $b\in\Mov(p)$ then $a_p\in\Mov(p)\cap O$. If $b\notin\Mov(p)$ then $\Mov(p)\cap I = \Mov(p)\cap A$, and this set is nonempty because $p\circ f$ is non-equivalent (Proposition 2.4); since $A = O$, the mutant is killed. But $g\circ f$ survives: $b\in\Mov(g)\cap I$ so it is non-equivalent, while $\Mov(g)\cap O = \Mov(g)\cap A = \varnothing$. So $\score_\Pi = 1 \not\Rightarrow \score_\Gamma = 1$.
\end{proof}

\begin{theorem}[3.2b (general $\Pi$)]
Theorem 3.2 uses the finiteness of $\Pi$ only to keep the escape set $A$ finite. Without it the containment $\Mov(p) \subseteq \Mov(g)$ weakens to a \textbf{finite-avoidance} condition. For \emph{arbitrary} $\Pi$, $\Pi$ is sufficient for $\Gamma$ iff \[\begin{aligned} &\forall g \in \Gamma,\ \forall b \in \Mov(g),\ \forall\, F \subseteq R \setminus \Mov(g)\ \text{finite},\\ &\qquad \exists p \in \Pi:\ b \in \Mov(p) \ \wedge\ \Mov(p) \cap F = \varnothing. \end{aligned}\] For finite $\Pi$ this reduces to Theorem 3.2 (take $F$ to be the escape set $A$). Exactly on infinite families over an infinite $R$ do the two forms differ. On $R = \mathbb{N}$ the regime $\Pi = \{\, \{0,k\} : k \ge 1 \,\}$ is sufficient for the guard target $\Mov(g) = \{0\}$, because for any finite $F \subseteq \mathbb{N}\setminus\{0\}$ some $k \notin F$ gives $\{0,k\} \cap F = \varnothing$; yet $\Pi$ contains no footprint $\subseteq \{0\}$, so Theorem 3.2's condition \emph{fails} while 3.2b's \emph{holds}. Theorem 3.2 is therefore the finite-$\Pi$ instance of the general law, and its finiteness hypothesis cannot be dropped. Both forms are machine-checked (\texttt{footprint\_characterization}, \texttt{footprint\_characterization\_general}; \S 11).
\end{theorem}

\begin{remark}[3.3 (composition is the wrong closure)]
Theorem 3.2 dissolves the temptation to define sufficiency by \emph{generation under composition}. Killing a regime's operators need not kill their composites. On $R = \{0,1,2\}$ with sole reachable/observed value $0$, and $a(0)=1$, $b(0)=2$, $b(1)=0$ (extended arbitrarily to the rest of $R$), both $a\circ f$ and $b\circ f$ die at $0$, yet $(b\circ a)(0) = b(1) = 0$, so $(b\circ a)\circ f$ is equivalent and unkilled. Composition acts on exactly the part of an operator that adequacy cannot see, since $\Mov(b\circ a)$ can be strictly smaller than both factors' footprints. So ``$\Pi$ generates the transformation monoid'' says nothing about what a score certifies. The governing order is footprint containment, not compositional generation.
\end{remark}

\setcounter{section}{3}
\section{The minimal sufficient regime, and the ceiling}
\begin{corollary}[4.1 (the value-guard basis; minimal size $n$)]
Let $|R| = n$. A regime $\Pi$ is absolutely sufficient iff it contains, for every $r \in R$, an operator with footprint $\{r\}$ --- a \emph{value guard} $\gamma_r$, ``if the result is $r$, return something else.'' The minimal absolutely-sufficient regime is $\{\gamma_r : r \in R\}$, of size exactly $n$.
\end{corollary}

\begin{proof}
Absolute sufficiency is sufficiency for $\mathcal{T}(R)$, whose footprints are all of $2^R$ (Remark 2.5). Apply Theorem 3.2b to the singleton target $\Mov(g) = \{b\}$ with $F = R \setminus \{b\}$, which is finite because $R$ is: sufficiency forces some $p\in\Pi$ with $b\in\Mov(p)$ and $\Mov(p) \cap (R\setminus\{b\}) = \varnothing$, i.e. $\Mov(p)=\{b\}$, a value guard for $b$. (Because $R$ is finite, the whole complement is an admissible $F$, so no finiteness hypothesis on $\Pi$ is needed here.) Conversely a guard per value satisfies 3.2b's condition for every target. Each of the $n$ singleton targets forces a distinct guard, so no smaller regime suffices.
\end{proof}

\begin{corollary}[4.2 (mechanical sufficiency requires a finite return type)]
A finite regime can be absolutely sufficient only when $R$ is finite. For an infinite return type, such as \texttt{int}, \texttt{String} or objects, \emph{no finite output-mutation regime is absolutely sufficient}.
\end{corollary}

\begin{proof}
Let $\Pi$ be finite and absolutely sufficient. For each $b \in R$, Theorem 3.2 applied to the singleton target $\{b\}$ yields some $p\in\Pi$ with $b\in\Mov(p)\subseteq\{b\}$, i.e. $\Mov(p)=\{b\}$. As $r \mapsto \{r\}$ is injective, $|\Pi| \ge |R|$, so $R$ is finite.
\end{proof}

Corollary 4.2 bounds \textbf{finite absolutely sufficient operator families}, not effective knowledge of reachability. Such families exist on finite return types: Booleans, enums, small tagged unions. On the return types of most real programs the absolute regime is unavailable, so the meaningful object is \emph{relative} sufficiency for a chosen footprint class (\S 5), which is the certificate a tool can actually offer.

\begin{corollary}[4.3 (extreme mutation is optimal on Booleans, deficient beyond)]
A constant operator \texttt{return c} has footprint $R \setminus \{c\}$. The constant regime is absolutely sufficient iff $n = 2$: then \texttt{return true}/\texttt{return false} have footprints $\{\mathrm{false}\}$/$\{\mathrm{true}\}$, exactly the two guards, while for $n \ge 3$ every constant footprint has size $\ge 2$, so no constant is a guard.
\end{corollary}

\begin{example}[4.4 (a distinction the constants cannot know)]
Let $R = \{a,b,c\}$, a program reaching all three, a suite observing only $\{a,b\}$. All three constants die, so the constant score is $1$. But the fault ``returns $b$ where it should return $c$'', with footprint $\{c\}$, is non-equivalent ($c\in I$) and unkilled ($\{c\}\cap O=\varnothing$). A perfect extreme-mutation score determines nothing about the $c$-outputs the suite never observed.
\end{example}

\begin{theorem}[4.5 (the ceiling --- exactly what a full score knows)]
For $|R| \ge 2$ and any $f$, $T$: \[ \score_{\mathcal{T}(R)}(f,T) = 1 \;\iff\; I \subseteq O \;\iff\; O = I, \] i.e. an absolute score of one holds \textbf{exactly when the suite exercises every reachable output}. This is the whole of what output mutation determines, and no more.
\end{theorem}

\begin{proof}
($\Leftarrow$) If $O = I$, every non-equivalent $g$ has $\Mov(g)\cap I \neq \varnothing$, hence $\Mov(g)\cap O \neq \varnothing$, so all die. ($\Rightarrow$) If $I \not\subseteq O$, the guard $\gamma_b$ for $b \in I\setminus O$ is non-equivalent and unkilled, so the score is below one.
\end{proof}

\begin{remark}[4.6 (the ceiling, and the first face of the intent residual)]
Theorem 4.5 is the operational content of output mutation. A full score certifies \textbf{output coverage}, that every value the program can return was observed, and the value guards are the cheapest regime making that exact. It knows nothing about faults separating two inputs mapped to the same output: if $f(x_1) = f(x_2)$ then $p(f(x_1)) = p(f(x_2))$ for every output operator, so no output mutant distinguishes them. Input-separating behavior is structurally outside the regime's knowledge, the first and purely structural piece of what the mechanical layer cannot reach.
\end{remark}

\setcounter{section}{4}
\section{Where knowability is decidable}
Fix a finite $\Pi$ and a finitely-presented target $\Gamma$. By Theorem 3.2, deciding sufficiency is deciding footprint containment, so its complexity is exactly that of the footprint representation.

\begin{proposition}[5.1 (the exact reach of a partial guard regime)]
The guards $\{\gamma_{r_1},\dots, \gamma_{r_k}\}$ are sufficient for exactly $\Gamma_{\max} = \{ g : \Mov(g) \subseteq \{r_1,\dots,r_k\} \}$.
\end{proposition}

\begin{proof}
By Theorem 3.2 the guards are sufficient for $g$ iff every $b\in\Mov(g)$ has a guard $\gamma_{r_i}$ with $b\in\{r_i\}\subseteq\Mov(g)$, i.e. $b\in\{r_1,\dots,r_k\}$; this holds for all $b\in\Mov(g)$ iff $\Mov(g)\subseteq\{r_1,\dots,r_k\}$.
\end{proof}

Proposition 5.1 is the usable form. A partial guard regime yields an explicit, checkable certificate: \emph{every guarded value the program can produce is exercised, hence any fault confined to the guarded values is caught}, with the guarded set a named parameter.

\begin{theorem}[5.2 (decidability spectrum)]
Let $\Pi$ and $\Gamma$ be finite. By Theorem 3.2, $\Pi$ is sufficient for $\Gamma$ iff \[\begin{aligned} &\forall g \in \Gamma\ \ \forall b \in \Mov(g)\ \ \exists p \in \Pi:\\ &\qquad b \in \Mov(p)\ \wedge\ \Mov(p) \subseteq \Mov(g), \end{aligned}\] so its decidability is that of this condition for the representation in which operators are given:
\begin{enumerate}
\item \textbf{Value tables.} $R$ is finite with $|R| = n$, and each operator is given as its table of $n$ values, so the input has size $N = (|\Pi| + |\Gamma|)\,n$. Sufficiency is decidable in time $O(|\Pi|\,|\Gamma|\,n) \subseteq O(N^2)$.
\item \textbf{Presburger-definable footprints.} $R = \mathbb{Z}$, and each operator is given by a Presburger formula $\varphi_p(x)$ defining $\Mov(p)$. Sufficiency is decidable.
\item \textbf{Total computable operators.} $R = \mathbb{N}$, and each operator is given as a program computing a total function $\mathbb{N} \to \mathbb{N}$, so each footprint is a decidable set. Sufficiency is undecidable; indeed the set of sufficient instances is not recursively enumerable.
\end{enumerate}
\end{theorem}

\begin{proof}
(1) Compute each footprint by one pass over its table. For each $g \in \Gamma$, scan $\Pi$ once to form $U_g = \bigcup\{\Mov(p) : p \in \Pi,\ \Mov(p) \subseteq \Mov(g)\}$, at $O(n)$ per operator, and test $\Mov(g) \subseteq U_g$; the displayed condition is equivalent to $\Mov(g) \subseteq U_g$ for every $g$. (2) With $\Pi$ and $\Gamma$ finite, the displayed condition is a single sentence of Presburger arithmetic, \[ \textstyle\bigwedge_{g \in \Gamma} \forall b\, \big(\varphi_g(b) \to \bigvee_{p \in \Pi} (\varphi_p(b) \wedge \forall y\, (\varphi_p(y) \to \varphi_g(y)))\big), \] whose truth is decidable (Presburger~\cite{presburger1929}). (3) Appendix A gives a computable map from Turing machines $M$ to instances $(\{h\}, \{g_M\})$ of total computable operators such that $\{h\}$ is sufficient for $\{g_M\}$ iff $M$ never halts on empty input. The non-halting machines form a set that is not recursively enumerable, so neither is the set of sufficient instances.
\end{proof}

\begin{remark}[5.3 (the spectrum runs through set containment)]
The P / decidable / undecidable gradient is that of subset containment for increasingly expressive set representations. No word problems or Cayley embeddings appear, because adequacy never composes operators (Remark 3.3). It is the containment order, and not a generation order, that governs whether knowability is decidable. So the second knowability boundary, whether the sufficiency question itself is answerable, is exactly the decidability of footprint containment.
\end{remark}

\setcounter{section}{5}
\section{What structure alone cannot determine}
\begin{proposition}[6.1 (coupling is not entailed)]
There exist a regime $\Pi$, program $f$, and suite $T$ under which every non-equivalent first-order $\Pi$-mutant is killed while a non-equivalent higher-order mutant survives.
\end{proposition}

\begin{proof}
Let $R = \{0,1,2\}$, $\Pi = \{a\}$ with $a: 0\mapsto 1, 1\mapsto 0, 2\mapsto 1$ (so $\Mov(a) = R$), and $f$ with $I = \{0,2\}$, $O = \{0\}$. The first-order mutant $a\circ f$ is killed at $0$. But $a\circ a: 0\mapsto 0, 1\mapsto 1, 2\mapsto 0$ has $\Mov(a\circ a) = \{2\}$: non-equivalent ($2\in I$), unkilled ($2\notin O$). So the score is $1$ against $\{a\}$ and below $1$ against its composition closure.
\end{proof}

The coupling-effect hypothesis (DeMillo, Lipton and Sayward~\cite{demillo1978}), that killing first-order mutants tends to kill higher-order ones, is therefore not entailed for output mutation. Its mechanism is the one in Remark 3.3: a composite's footprint can be strictly smaller than its factors'. By Theorem 3.2 a higher-order mutant is simply an operator with a footprint, and the composition closure may contain footprints the regime leaves uncovered. The hypothesis is a statistical claim about typical faults. Proposition 6.1 shows that it is no theorem here, and nothing more than that; it says nothing against the hypothesis in practice.

\setcounter{section}{6}
\section{Why the theory is program-independent}
\begin{proposition}[7.1 (program-independent subsumption)]
For output operators $p, g$: \emph{every test that kills $p\circ f$ also kills $g\circ f$, for every program $f$}, iff $\Mov(p) \subseteq \Mov(g)$.
\end{proposition}

\begin{proof}
($\Leftarrow$) A test $x$ kills $p\circ f$ iff $f(x) \in \Mov(p) \subseteq \Mov(g)$, so it kills $g\circ f$. ($\Rightarrow$) If $b \in \Mov(p)\setminus\Mov(g)$, a program reaching $b$ with a suite observing $b$ kills $p\circ f$ but not $g\circ f$.
\end{proof}

For finite $\Pi$, Theorem 3.2 reads: \textbf{for every target $g$ and every moved value $b\in\Mov(g)$, some $p\in\Pi$ both moves $b$ and subsumes $g$ uniformly over programs}. Its pointwise coverage clause is essential, since one subsuming mutant per target is insufficient. For example, footprints $\Mov(p)=\{0\}$ and $\Mov(g)=\{0,1\}$ satisfy subsumption, but with $I=\{1,2\}$ and $O=\{2\}$ the regime $\{p\}$ has full score while $g$ survives non-equivalently. Subsumption without coverage of every moved value fails to establish sufficiency.

\begin{proposition}[7.2 (the factoring that buys program-independence)]
For an output operator the detection set factors through the footprint: $\Det(p\circ f) = \{x : p(f(x)) \neq f(x)\} = f^{-1}(\Mov(p))$. So $p$ enters detection only through the program-independent object $\Mov(p)$. The contrast with program-text mutation is subtler than syntax against semantics, since any mutant's detection set is semantic. A program-text schema's mutant depends on the \emph{text} of $f$, so in general its detection is a function of the (schema, source) pair rather than of the schema alone, and it can vary across programs computing the same $f$. Particular schemas still admit program-independent statements, as the relational and conditional operator results do at the point of mutation (\S 11), but each must be derived for its schema. What output operators have is a general reduction: every operator in the class is characterized by its footprint, which is why the knowability theory of \S 3 is available for the whole class at once.
\end{proposition}

\setcounter{section}{7}
\section{The cost of the knowledge}
\begin{theorem}[8.1 (minimum certifying suite)]
Fix an absolutely-sufficient regime and a program $f$ with reachable set $I = f(D)$. A suite $T$ achieves $\score(f,T) = 1$ iff $O = I$. \textbf{If $I$ is finite}, the minimum certifying suite has size $\sigma(f) = |I| = |f(D)|$ (one test per reachable value). \textbf{If $I$ is infinite}, no finite suite is certifying: finite $T$ has finite $O = f(T)$, so $O \neq I$.
\end{theorem}

\begin{proof}
By Theorem 4.5 the score is $1$ iff $O = I$. If $I$ is finite, a suite with $O = I$ has, for each $r \in I$, some $x$ with $f(x) = r$, so $|T| \ge |I|$; one $x$ per value gives $|T| = |I|$. If $I$ is infinite, $O = f(T)$ is finite for finite $T$.
\end{proof}

\begin{remark}[8.2 (the sample complexity of knowledge)]
$\sigma(f)$ is the \textbf{teaching dimension} of $f$ with respect to the concept class $\mathcal{C}_\Pi(f) = \{f\} \cup \{p \circ f : p \in \Pi\}$, i.e. the size of a smallest teaching set for $f$ in $\mathcal{C}_\Pi(f)$ (Goldman and Kearns~\cite{goldman1995}): the minimum number of labeled examples, tests with their observed outputs, that distinguish $f$ from every non-equivalent mutant the regime expresses. For output mutation it is exactly the number of reachable outputs. Theorem 3.2 says \emph{which} faults a regime can certify against, and Theorem 8.1 says \emph{how many tests} the certification costs. So the mechanically-knowable profile of a function's output behavior is both characterized and \emph{priced}.
\end{remark}

\setcounter{section}{8}
\section{The oracle-relative boundary and the pseudo-tested method}
Our model's one load-bearing simplification is the exact oracle (Remark 2.6), and it is also the one that most bounds practical relevance, because the phenomenon that motivates extreme mutation, the \emph{pseudo-tested method}, is a weak-oracle phenomenon by construction. This section relativizes the theory to an arbitrary oracle and characterizes exactly what a weak oracle hides. \S 10 then separates that observational layer from the intent residual.

\begin{definition}[9.1 (oracle)]
An \emph{oracle} is a map $\omega : R \to \Omega$ recording what the suite's assertions observe about a returned value. The exact oracle is $\omega = \mathrm{id}$; a suite checking only a field, a hash, a type tag, or nothing is a non-injective $\omega$.
\end{definition}

\begin{definition}[9.2 (oracle-relative detection)]
$T$ \emph{$\omega$-kills} $p\circ f$ iff $\omega(p(f(x))) \neq \omega(f(x))$ for some $x \in T$; $p\circ f$ is \emph{$\omega$-equivalent} iff equality holds for all $x$. The oracle-relative detection set is $\Det_\omega(p) = \{ r : \omega(p(r)) \neq \omega(r) \}$.
\end{definition}

\begin{proposition}[9.3 (the relativized reduction)]
$p\circ f$ is $\omega$-equivalent iff $\Det_\omega(p)\cap I=\varnothing$, and $T$ $\omega$-kills it iff $\Det_\omega(p)\cap O\ne\varnothing$. Also $\Det_\omega(p)\subseteq\Mov(p)$, with equality for injective $\omega$. The set-system sufficiency results (Theorems 3.2 and 3.2b) and subsumption characterization (Proposition 7.1) therefore apply to the actual families of $\Det_\omega$ sets. The singleton-guard ceiling and its suite-size consequence require a \textbf{nonconstant oracle}: only then can every singleton detection set be realized by an output operator. Effective decidability statements additionally require the stated effective representation of $\Det_\omega$ itself; a simple $\Mov$ representation alone does not ensure it for arbitrary $\omega$. With constant $\omega$, all mutants are $\omega$-equivalent, every score is vacuously one, and every regime is absolutely $\omega$-sufficient, independently of output coverage.
\end{proposition}

\begin{proof}
Identical to Proposition 2.4 reading $\omega\circ p$ against $\omega$; containment is immediate.
\end{proof}

\begin{remark}[9.3b (the footprint abstraction partially gives way)]
Under a non-injective $\omega$, $\Det_\omega(p)$ reads $\omega \circ p$, so \emph{where} $p$ sends the values it moves, invisible to adequacy under the exact oracle (Remark 2.5), becomes visible again: two operators with equal $\Mov$ can have different $\Det_\omega$. Corollary 4.3 is where this bites. A constant has $\Det_\omega(\text{`return }c\text{'}) = R \setminus \omega^{-1}(\omega(c))$. For \textbf{finite} $R$ and \textbf{nonconstant} $\omega$, the constant regime is absolutely $\omega$-sufficient iff $|R| = 2$. On two values a nonconstant $\omega$ necessarily separates them ($\omega(\mathrm{true}) \neq \omega(\mathrm{false})$), so each constant's detection set is the other value's singleton; for $|R| \ge 3$, a singleton detection set $R \setminus \omega^{-1}(\omega(c)) = \{b\}$ for every $b$ would put all of $R$ in one $\omega$-class, i.e. make $\omega$ constant. So ``extreme mutation is optimal on Booleans'' survives relativization for every oracle that inspects the boolean at all, and fails only for the constant oracle, under which every score is vacuously one (Proposition 9.3).
\end{remark}

Where $\Mov$ and $\Det_\omega$ differ lies the interesting content. Under a weak oracle the ceiling stays where it was: for any non-constant $\omega$ and any value $b$ there is an operator with $\Det_\omega(p) = \{b\}$, so the absolute $\omega$-score is $1$ iff $I \subseteq O$. Output coverage remains exactly what a full score knows, provided the suite asserts \emph{something}. What weakening the oracle changes is \emph{which regimes} reach the ceiling, and that is what makes a covered mutant survive.

\begin{proposition}[9.4 (pseudo-testedness, characterized)]
Let $f$ be covered by $T$ (so $O \neq \varnothing$). The constant mutant \texttt{return c} is \textbf{pseudo-tested} --- it changes a value the program genuinely returns, yet no test in $T$ detects the change under oracle $\omega$ --- iff \[ \Mov(\text{`return }c\text{'}) \cap I \neq \varnothing \quad\text{and}\quad \Det_\omega(\text{`return }c\text{'}) \cap O = \varnothing, \] equivalently $I \neq \{c\}$ (some reachable output is not $c$, so the constant is non-equivalent under the \textbf{exact} oracle) and $O \subseteq \omega^{-1}(\omega(c))$ (every observed output is oracle-indistinguishable from $c$, so the \textbf{weak} oracle sees no change).
\end{proposition}

Here the crux is that the two conditions read non-equivalence and survival under \emph{different} oracles. Non-equivalence must be exact-oracle. A paradigm pseudo-tested method is one whose output no assertion inspects at all, so \emph{every} reachable output lies in $c$'s $\omega$-class ($I \subseteq \omega^{-1}(\omega(c))$) and the mutant is $\omega$-\emph{equivalent}; yet its return value genuinely differs from the original on some input ($\Mov \cap I \neq \varnothing$), which is exactly the fault the weak oracle fails to catch. Requiring $\omega$-non-equivalence, the natural but wrong reading $\Det_\omega \cap I \neq \varnothing$, would exclude this case, the very phenomenon the notion names. Under the exact oracle $\omega = \mathrm{id}$ we have $\Det_\omega = \Mov$ and the two conditions collapse to $O = \{c\}$ against $I \neq \{c\}$: the suite observes only $c$ while the program returns more.

\begin{proof}
$\omega$-survival is $\Det_\omega(\text{`return }c\text{'}) \cap O = \varnothing$, i.e. $O \subseteq \omega^{-1}(\omega(c))$. Exact-oracle non-equivalence is $\Mov(\text{`return }c\text{'}) \cap I \neq \varnothing$; since $\Mov(\text{`return }c\text{'}) = R \setminus \{c\}$ this is $I \neq \{c\}$. Under $\omega = \mathrm{id}$, $\Det_\omega = \Mov$ and $\omega^{-1}(\omega(c)) = \{c\}$.
\end{proof}

This is the model's account of the empirical phenomenon. A method is pseudo-tested exactly when the suite's assertions collapse everything it observes into one oracle class, so replacing the body with a constant in that class changes nothing the suite can see. Mechanically, the regime establishes that the returned value changed ($\Mov \cap I \neq \varnothing$), and the gap $\Mov(p) \setminus \Det_\omega(p)$ is exactly what this oracle hides. Closing it takes an assertion that pins the value. Whether the value \emph{should} be pinned, that is, whether the hidden distinction matters, is a question about the specification rather than the oracle (\S 10). This account also explains why extreme mutation is a productive \emph{detector} even though the constant regime is a weak \emph{certifier} (Corollary 4.3): the two roles differ, and the surfaced gap is a candidate assertion the suite is missing.

\begin{proposition}[9.4b (the mixed ceiling --- the score a tool actually reports)]
Definition 9.2 discounts $\omega$-equivalent mutants, so the absolute $\omega$-score of the paragraph above is not the number a tool reports. Production tools (Descartes, PIT) count a mutant as non-equivalent when it changes the returned value, the \emph{exact} oracle, and as killed when the suite notices, the \emph{weak} oracle $\omega$, which is exactly the mixed reading Proposition 9.4 adopts. Applied to the ceiling, that reading gives a strictly stronger theorem. The absolute \textbf{mixed} score (exact-oracle non-equivalence, $\omega$-kills) is $1$ iff \[ O = I \quad\text{and}\quad \omega^{-1}(\omega(b)) = \{b\}\ \text{ for every } b \in I, \] i.e. the suite observes every reachable output \emph{and} the oracle separates every reachable value from every other. Under the exact oracle the second clause is automatic ($\omega = \mathrm{id}$ is injective) and this collapses to Theorem 4.5.
\end{proposition}

\begin{proof}
($\Leftarrow$) Let $p$ be non-equivalent under the exact oracle: some $b \in \Mov(p) \cap I$. Then $b \in O = I$ and $p(b) \neq b$, and $\omega^{-1}(\omega(b)) = \{b\}$ forces $\omega(p(b)) \neq \omega(b)$, so $T$ $\omega$-kills $p$ at $b$; hence every exact-non-equivalent mutant is $\omega$-killed. ($\Rightarrow$) If $b \in I \setminus O$, the guard $\gamma_b$ is exact-non-equivalent and $\omega$-unkilled (its only moved value $b$ is unobserved), so it survives. If some $b' \neq b$ shares $b$'s $\omega$-class with $b \in I$, the operator sending $b \mapsto b'$ is exact-non-equivalent yet has $\Det_\omega = \varnothing$, so it survives. Either failure drops the score below one.
\end{proof}

\begin{remark}[9.4c (the scope of an output oracle)]
Definition 9.1 lets an assertion depend only on the returned value. Real assertions can also depend on the input and on other calls, and two cases fall outside the model in different ways.
\end{remark}

\begin{itemize}
\item \emph{Input-dependent checks.} Suppose $f(x_1) = f(x_2) = r$ and the suite asserts the value returned for $x_1$ but never inspects the one for $x_2$. Detection is then a per-call oracle $\omega_x$ rather than a single $\omega$ on $R$, so $\Det_\omega(p) \cap O$ no longer determines killing and Proposition 9.3's reduction no longer applies as stated. Detection of a mutant is still the union of per-call events, one for each executed call whose result the mutant changes.
\item \emph{Joint checks.} An assertion over several results, such as \texttt{assert f(x1) != f(x2)}, is not even a union of per-call events. With $f(x_1) \neq f(x_2)$, the constant mutant makes the two results equal and is detected, while a mutant that changes only one of them, to that same constant, is not.
\end{itemize}

We formalize neither generalization. \S 9.5 measures how often real suites stay within the per-call form, using a prediction that holds for every per-call oracle.

\setcounter{subsection}{4}
\subsection{Empirical: uniform output operators on four Python libraries}
Our theory makes two predictions a test suite can be held to. First, whether a covered function is pseudo-tested depends on the oracle (Proposition 9.4). Second, under the model a constant mutation is detected exactly when one of its point changes is. Write $s_{r \to c}$ for the \textbf{point swap} that sends the value $r$ to $c$ and fixes everything else. For observed outputs $O$,

\[ \Det_\omega(\text{`return }c\text{'}) \cap O \;=\; \bigcup_{r \in O \setminus \{c\}} \big(\Det_\omega(s_{r\to c}) \cap O\big), \]

so \texttt{return c} is killed iff some $s_{r \to c}$ with $r \in O$ is killed (Proposition 9.3). This holds for any \emph{per-call} oracle as well (Remark 9.4c), provided changing one call's result leaves unchanged which other calls occur: the constant changes exactly the calls the swaps change between them, and each call's detection event is the same under both. So agreement with this prediction measures how often real suites stay within per-call checking, and a disagreement identifies a check outside it.

\textbf{What this tests, and what it does not.} The theory of \S \S 2--8 assumes pure total functions. Our experiment applies the theory's operator, post-composition on the returned value, to real functions, and some of the sampled functions are impure: inflect's \texttt{def*} methods register a user-defined inflection, and boltons' \texttt{LRI.setdefault} writes to a cache. For such functions the prediction still applies to the recorded execution traces, as long as perturbing a returned value leaves the calls and side effects the tests observe unchanged. So the study tests the output-transformation prediction on real execution traces, some of them from stateful programs; it validates no more of the pure-function adequacy model than that.

\textbf{Design.} We pinned four libraries to release commits: boltons 26.2.0, inflect 7.6.0, toolz 1.2.0 and humanize 4.16.0. Each candidate is a public function or method in a public module, and it is mutated as the model prescribes. An injected decorator, innermost on the function, returns $p(f(x))$ in place of $f(x)$ at the outermost call, so recursive calls inside $f$ stay unperturbed. Each project's own suite is used, including its doctests where the project runs them. A test is \emph{usable} if it passed twice with the decorator installed and inactive, and also on the unmodified checkout. A recording run logs every returned value of every candidate, per test. A function is \emph{eligible} if some usable test calls it, every observed output has a stable representation (no memory addresses), and it returns something other than \texttt{None} (void functions are outside the model, Remark 2.6). We drew a seeded sample of at most 40 eligible functions per library. For each sampled function, $c$ is a type-appropriate constant (\texttt{0}, \texttt{""}, \texttt{[]}, \texttt{\{\}}, \texttt{False} and so on) chosen so that some observed output differs from it. When no single built-in type covers the outputs, $c$ is \texttt{None}, and we report that subset separately. Each function receives the constant mutant \texttt{return c} and the swaps $s_{r \to c}$ for every observed $r \neq c$, sampled down to 12 where there are more. Each mutant runs only the function's covering usable tests. A test failure counts under the \textbf{value oracle} when the test's own check rejects the result: an \texttt{AssertionError} raised in test code, \texttt{pytest.fail} or \texttt{pytest.raises} failing, or a doctest output mismatch. It counts under the \textbf{any-failure oracle} when the test fails in any way, including an exception from library code or a timeout.

Of 646 candidates, 336 were eligible: 147 were not covered by a usable test, 94 returned values without a stable representation (mostly iterators and generators in toolz), and 69 returned only \texttt{None}. We sampled 131 (40, 40, 34 and 17) and ran 985 mutants: 131 constants and 854 swaps, against 1,853 usable tests. Every constant mutant was applied at least once. Nine tests behave differently with the decorator installed and are excluded from the usable set. In boltons, four tests pickle classes made by factories that read the caller's frame, or inspect frames directly. In inflect, five tests check \texttt{typeguard} runtime validation, which does not instrument a function wrapped by our decorator.

One function's outputs vary between runs, so not every swap was applied; it is counted as untestable rather than as a swap that went undetected. With the value oracle the prediction held for 85 of 86 and 41 of 42. Both exceptions are boltons functions whose constant is \texttt{None}: the constant makes a test crash before reaching the assertion that catches the individual swaps, so the value oracle never sees it. That is the type artifact the type-preserving subset avoids, and in that subset the prediction held without exception: 59 of 59 complete, and 36 of 36 (value) and 37 of 37 (any failure) sampled. No joint check of the kind in Remark 9.4c surfaced in this sample.

\textbf{Threats to validity.}

\begin{itemize}
\item \emph{The direction of the gap is fixed by construction.} Any-failure kills include value kills, so only the gap's magnitude carries information, and a crash can pre-empt an assertion (the two value-oracle exceptions).
\item \emph{The value oracle is a family.} A value-pinning \texttt{==} is close to $\omega = \mathrm{id}$, while a check on a field, a length or a type is a strictly weaker $\omega$; the value column mixes them.
\item \emph{Reachable outputs are approximated by observed ones.} Non-equivalence of each constant is guaranteed, since $c$ differs from some observed output, but the swaps cover only observed values.
\item \emph{Value identity is by representation.} Swaps match values by \texttt{repr}, which excludes 94 candidates and makes swaps on nondeterministic outputs unreliable. We count each operator's applications and treat unapplied swaps as missing.
\item \emph{Some sampled functions are stateful.} The model assumes pure functions; for methods with side effects the study tests the prediction on the observed traces only (see ``What this tests'' above).
\item \emph{The decorator has side effects.} It excludes nine tests, and in inflect it removes \texttt{typeguard}'s runtime checks from decorated methods in every run.
\item \emph{The sample is small.} Four Python libraries and 131 functions bear on how often real suites fit the model's form, not on how prevalent pseudo-testing is in general.
\end{itemize}

\setcounter{section}{9}
\section{The intent residual}
Our results separate three kinds of knowledge about a function's output behavior (\S 1.2). The theory determines the first two within its model, and the third needs a source outside the program.

\textbf{Semantic distinguishability, and the evidence for it.} The ceiling theorem characterizes a semantic score that excludes genuinely equivalent mutants, without providing a procedure for recognizing those mutants. For a singleton guard $\gamma_b$, an observed kill proves $b\in O$, whereas a surviving guard proves only $b\notin O$. Two possibilities remain: $b\notin I$ (equivalent) or $b\in I\setminus O$ (reachable but unobserved). A witnessed execution reaching $b$ resolves that ambiguity positively, and a justified equivalence proof can resolve it negatively; unsuccessful search alone cannot.

A finite return type makes the absolute guard family finite (Corollary 4.2), and leaves reachability undecidable. For any machine $M$, the total Boolean function $f_M(n)$ that returns whether $M$ halts within $n$ steps reaches \texttt{True} iff $M$ halts. Thus a tool computing all reachable outputs, or deciding equivalence of the \texttt{True} guard, would decide halting. Theorem 5.2 concerns sufficiency of represented operator footprints rather than equivalence of their compositions with arbitrary programs. Full output coverage is mechanically decidable on a finite, exhaustively executable input domain, or under additional reachability certificates. Otherwise the honest operational result records observed kills, proven equivalences, and unresolved candidate-equivalents separately. A certificate modulo those candidates is conditional on their equivalence; it is weaker than the unconditional score of Definition 2.3. Theorem 8.1 prices a certifying suite when it exists, without giving a general algorithm to find it.

\textbf{Observational distinguishability.} What the suite's assertions see is the oracle-relative detection set (\S 9). For each mutant, $\Mov(p) \setminus \Det_\omega(p)$ is exactly the set of changed values this oracle hides, and Proposition 9.4 characterizes when that hides a whole constant mutation. This is a property of the pair (program, oracle), and the model determines it fully: given the reachable outputs and the oracle, nothing about it is left open. Its scope is an oracle that reads each returned value on its own (Remark 9.4c).

\textbf{Specification relevance: the intent residual.} Neither layer says whether a distinction \emph{matters}. An oracle blind to a change is no evidence that the change is harmless. An author may intend two outputs to be interchangeable, in which case leaving the distinction unchecked is correct, and an assertion may detect a difference the specification ignores. Which of the certified distinctions bear on what the program is supposed to do is fixed neither by the program text nor by its oracle. We call this the \emph{intent residual}. Two parts of it are structural: faults that separate inputs mapped to the same output lie outside output mutation entirely (Remark 4.6), and a hidden distinction $\Mov(p) \setminus \Det_\omega(p)$ is resolved only by deciding whether the value should be pinned. Resolving either takes a specification supplied from outside the program and its suite: an authored intent test stating that on this input the returned value \emph{is} what it should be, a reference implementation, or a formal contract. Our theory leaves open which source must supply it; what it shows is that the program and its oracle cannot.

The knowability boundary therefore runs neither between easy and hard nor between cheap and expensive. It runs between output behavior that is observed or proved, semantic equivalence that remains unresolved, and intent that the program text leaves open. This paper's theorems characterize the first completely. That the other two are finite and named is what makes the division a workflow rather than a fog.

Underneath this paper lies a formal notion older than mutation tools. Budd and Angluin~\cite{budd1982} call a test set $T$ \emph{adequate} for $P$ relative to a neighborhood $\Phi(P)$ of alternative programs if every alternative is either equivalent to $P$ or fails on some test. With $\Phi(P) = \{p \circ f : p \in \Pi\}$ that is exactly a score of one against $\Pi$. Howden~\cite{howden1982} defines the same notion function by function. There $T$ is \emph{effective} for $f$ relative to an error class $S_f$ if any $f' \in S_f$ that agrees with $f$ on $T$ agrees with it everywhere, and \emph{complete} if it is effective for every component function a method targets. He uses the definition to compare weak, strong and trace mutation, branch, domain and functional testing. Both papers fix the program and its class of alternatives. Budd \& Angluin ask whether an adequate set exists and whether one can be recognized or generated: every finite neighborhood has one, existence is undecidable in general, and computable recognizers are tied to decidable program equivalence. Neither paper relates adequacy for one class to adequacy for another, which is the question Definition 3.1 asks over all programs and suites: $\Pi$ is sufficient for $\Gamma$ iff adequacy relative to $\{p \circ f : p \in \Pi\}$ implies adequacy relative to $\{g \circ f : g \in \Gamma\}$ for every $f$ and $T$. Howden reports the nearest earlier result of that shape, from Brooks: for shape-preserving errors in a restricted class of recursive Lisp programs, a test set complete for single trace mutations is complete for repeated ones. That is a coupling theorem for one program class, whereas Theorem 3.2 characterizes sufficiency for the whole output-operator class. Budd \& Angluin's existence question also has a sharp answer here: against all output operators a finite adequate suite exists iff $f(D)$ is finite (Theorem 8.1).

True semantic subsumption, the order a completeness theorem would rank against, is undecidable (Kurtz et al.~\cite{kurtz2015}). Later constructive results are relative by construction: sufficient operators are found experimentally against a pool (Offutt et al.~\cite{offutt1996}), while minimal and dominator sets are test-set- and pool-relative (Ammann et al.~\cite{ammann2014}). Shin and Bae~\cite{shin2016} give the closest formal framework: it represents the behavioral differences of mutants over a given set of tests as vectors and recovers mutant-set minimization and mutation-based fault localization within it. It is offered as a framework rather than a theory with theorems, and its object is a fixed test set and mutant pool. Program-independent results do exist, namely the sufficient replacement sets for relational and conditional operators (Kaminski, Ammann and Offutt~\cite{kaminski2013}; Just et al.~\cite{just2012}): from a clause's truth table they show that a few replacements subsume the rest \textbf{at the point of mutation, for any predicate in any program}. That is the same kind of program-independent statement the present theory makes, for one operator schema at a time. Theorem 3.2 makes it for the whole output-operator class, as an exact characterization rather than a sufficient set. Likewise the coupling effect is more than an assumption. Wah's~\cite{wah2003} analyses establish it under restricted fault models, so the honest statement is ``unproven in general,'' not ``never proven.''

Two of this paper's constructs are prior art under other names. Theorem 4.5's ceiling, that a full score means every reachable output was observed, is the coverage notion behind the \textbf{output-uniqueness} criterion of Alshahwan and Harman~\cite{alshahwan2014}, reached here as a theorem about footprints rather than posited as a criterion. Our value/oracle gap of \S 9 is \textbf{checked coverage} (Schuler and Zeller~\cite{schuler2013}), the existing dynamic measure of whether an assertion actually constrains a computed value. Extreme mutation and pseudo-testedness are due to Niedermayr et al.~\cite{niedermayr2016} and Vera-P\'{e}rez et al.~\cite{veraperez2019}, with the Descartes tool (Vera-P\'{e}rez et al.~\cite{descartes2018}). We recover extreme mutation as the $n = 2$ optimum (Corollary 4.3; Remark 9.3b for weak oracles) and characterize pseudo-testedness in the model's own terms (Proposition 9.4), and we take the teaching-dimension reading from Goldman and Kearns~\cite{goldman1995}.

\textbf{What is new.} An exact characterization, for finite and for arbitrary regimes, of uniform sufficiency between output-operator families, expressed through their semantic footprints (Definition 3.1; Theorems 3.2 and 3.2b), with a constructive counterexample whenever it fails. No result in the table implies it: output uniqueness concerns the absolute case only and is no theorem; the point-of-mutation sufficiency results fix one operator schema and give a sufficient set rather than a characterization; and the subsumption results are relative to a test set and pool. Its consequences are the value-guard basis (Corollary 4.1), the ceiling (Theorem 4.5), the decidability spectrum (Theorem 5.2), the cost (Theorem 8.1) and the oracle relativization (\S 9). Proposition 6.1 clarifies Remark 3.3 rather than standing as an independent contribution. Two companion manuscripts, withheld here for review, develop what this paper's residual points to: one the effect/meaning frame and the decidable-coupling result, the other the teacher-supplied negative sign.

\textbf{Scope.} Our theory concerns output/extreme mutation of pure total functions. \S \S 2--8 assume an exact oracle, which \S 9 removes. It stops short of general program-text mutation and makes no claim about the coupling hypothesis for program-text faults. Its effect layer has an undecidability of its own, general footprint containment (Theorem 5.2(3)), which we characterize rather than dissolve. Our central quantitative result, that a full score equals output coverage, is deliberately modest: it says what a score \emph{means}, and leaves open whether a tool should compute it in preference to measuring output coverage directly.

\setcounter{section}{11}
\section{Conclusion}
For one operator class we replace a heuristic, a high score read as adequacy on the strength of the coupling hypothesis, with a theorem about what the score determines. The mechanically knowable profile of a function's output behavior is exactly characterized: which regime suffices to certify it (Theorem 3.2), the minimal such regime (Corollary 4.1), the exact content of a full score (Theorem 4.5, output coverage), where that knowledge is achievable (finite types) and decidable (footprint containment), and what it costs ($|f(D)|$ tests). Relative to an oracle, the theory also says exactly which changes the suite's assertions hide. What it leaves open is which of the certified distinctions bear on what the program is supposed to do; that intent residual takes a specification from outside the program and its oracle. For this class a mutation score is thus an object with a characterized semantics rather than a quantity trusted empirically. The line between what a tool can know about a function and what requires a specification is drawn exactly, and the central characterization is checked by machine.

\section{Undecidability of sufficiency for computable operators}
This appendix proves Theorem 5.2(3). Operators are total functions $\mathbb{N} \to \mathbb{N}$ given as programs; an instance is a pair of finite lists of such programs, $(\Pi, \Gamma)$.

\textbf{Construction.} Fix the operator $h(k) = k + 1$ if $k$ is odd and $h(k) = k$ otherwise. It is total, and $\Mov(h) = \{k : k \text{ odd}\}$. For a Turing machine $M$ run on empty input, let

\[ g_M(k) = \begin{cases} k + 1 & \text{if } M \text{ halts within } k \text{ steps},\\ k & \text{otherwise,} \end{cases} \]

The operator $g_M$ is total: computing $g_M(k)$ simulates $M$ for at most $k$ steps and always terminates. A program for $g_M$ is obtained computably from a description of $M$, so $M \mapsto (\{h\}, \{g_M\})$ is a computable map into instances of total computable operators. Its footprint is $\Mov(g_M) = \{k : M \text{ halts within } k \text{ steps}\}$. Halting within $k$ steps is monotone in $k$, so $\Mov(g_M) = \varnothing$ if $M$ never halts, and $\Mov(g_M) = [t, \infty)$ if $M$ halts after exactly $t$ steps.

\textbf{Claim.} $\{h\}$ is sufficient for $\{g_M\}$ iff $M$ never halts.

\begin{proof}
By Theorem 3.2 with the single operator $h$, sufficiency holds iff every $b \in \Mov(g_M)$ satisfies $b \in \Mov(h) \subseteq \Mov(g_M)$. If $M$ never halts, $\Mov(g_M) = \varnothing$ and the condition holds vacuously. If $M$ halts after $t$ steps, $\Mov(g_M) = [t, \infty)$ contains an even number $b$, and $b \notin \Mov(h)$, so the condition fails at $b$.
\end{proof}

The set of machines that never halt on empty input is not recursively enumerable, and the map above reduces it to the set of sufficient instances; hence that set is not recursively enumerable, and in particular sufficiency is undecidable for total computable operators. The construction uses only Theorem 3.2, which is mechanized; the reduction itself is not.
